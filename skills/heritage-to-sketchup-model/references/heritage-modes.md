# 资料模式与项目约定

## 三种模式

完整图纸：读取 stage-reading.md、stage-topology.md、stage-production.md、stage-qa.md、stage-delivery.md 的当前阶段；沿用复制的验证器。所需图纸确实缺失时，解释缺口并确定是否改为推演，不静默宣称图纸交付合格。

平面＋效果图：先验证平面的单位、方向、控制轮廓、标高及此次改动范围。按建筑列出屋顶类型、正脊与檐口趋势、开间、门窗虚实、材料和主次等级。参考角度不足之处记作推定，优先用其他角度或参考模型补充。只问会改变形体或使用功能的关键疑问，其余采用已授权的合理估计并记录。

局部修订：读取现有模型及用户改动，圈定构件与关联范围。修改标记不重建几何；修改低廊端头需要同时处理对应瓦、望板、椽檩与封板，但无需重新核对未变的场地平面。结束时检查差异及同类对象是否漏改。

## 项目状态

沿用项目已有状态文件；缺少时记录以下语义字段即可，不再创建重复状态系统：
- mode: measured_drawings / plan_reference / existing_revision。
- source_authority: 各事项采用哪个文件、视角或用户决定。
- fixed_constraints: 已确认的尺寸、布局、形态；含确认原文和适用范围。
- inferred_parameters: 推定值、理由、来源、置信程度及待定项。
- building_families: 各栋差异、可共用组件、不可共用的例外。
- changes: 构件ID、旧新版本、改动原因、依赖范围、检查证据。
- review: 用户选择的方式、已通过范围、待核实项，禁止自动升级为通过。

先形成简明特征表并核对代表性样板；无需每步等用户确认。用户指定关键节点审核时才暂停相关工作。

## 不可泛化的项目经验

某项目厢房不起翘、低廊不设斗拱、夹板厚60mm、地面高差100mm，均不构成其他项目默认值。木封板是否存在、位于哪层枋间、是否通风，要按当前参考、建筑用途和构件关系决定。仿古效果图可支持设计解释，不能单独支持史实断代。
